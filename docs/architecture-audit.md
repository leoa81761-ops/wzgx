# 架构审计

对照线上 main `f289cee`（2026-10-12）。产品目标是：每个用户、每个公众号都有自己的写法，文章往前 5% 靠，界面能看懂、能操作。这篇只记已经在代码里核对过的模型和缺口。后面的 PR B 做引导和表单简化，PR C 做人格、标题和爆款结构。

## 领域模型

会员额度挂在用户上。写作设置挂在公众号的计划上。一篇文章从计划长出来，再落到任务。

```
users
  └─ wx_account            一个用户可绑多个号（高级版 / 买断版最多 5 个）
       └─ writing_plan     一个号可以有多个计划；每条计划只指向一个号
            ├─ plan_extra  开头、结尾、栏目、素材、风格画像，以及本 PR 补上的关键词、读者、禁用词、垂类、选题方式、配图
            ├─ article_task
            │    └─ article
            ├─ topic_coverage / topic_weight / 选题否决 / 指定题目
            └─ 自动发布开关（按计划）
```

相关但不属于某一个号的数据：

| 数据 | 归属 | 说明 |
| --- | --- | --- |
| 每日 / 周期额度、加量包 | 用户 | 多个号共用一份额度。这是会员规则，不是计划设置 |
| 风格画像 `style_profile`、试写、样稿 | 用户 | 计划可以用 `profile_id` 指向一条画像。学习「修改差异」目前一个用户只写一条 |
| 素材 `user_asset` | 用户 | 计划用 `asset_id` 选用。必须是这个用户自己的素材 |
| 垂类资料包 | 全站 | 计划可以指定 `vertical_key`。留空时仍按方向里的关键词匹配 |
| 敏感词、来源名单 | 全站 | 计划自己的禁用词额外并进这一篇的审核，不替换全站词表 |
| 服务配置、支付、登录 | 站点 | 和管理员配置中心有关，和某个号的写法无关 |

一条计划上已经能独立保存、并且生成时会读到的设置：方向、风格、排版、篇幅、周期、时段、每天篇数、固定开头、固定结尾、栏目、关键词、读者、禁用词、垂类资料包、选题方式（自动 / 只按方向轮换 / 优先热点 / 先确认选题）、配图（自动 / 不用 AI / 只要封面 / 优先素材）、自动发布。

## 页面和流程

| 路径 | 页面 | 做什么 |
| --- | --- | --- |
| `/` | 落地页 | 介绍和套餐 |
| `/login` `/register` | 登录、注册 | 手机号或邮箱。注册验证码默认关 |
| `/legal/:docType` | 协议 | 同意版本 |
| `/tutorial` `/help` `/examples` `/about` | 教程、帮助、示例、关于 | 静态说明 |
| `/pricing` | 定价和支付回跳 | 支付宝返回落在这里 |
| `/complaint` | 投诉 | 公开提交 |
| `/reconsent` | 重新同意 | 撤回协议后拦住登录后的页面 |
| `/app` | 工作台 | 额度、各号计划、启动或暂停 |
| `/app/accounts` | 公众号 | 绑定、检测、解绑，链到这个号的计划 |
| `/app/stats/:id` | 阅读和周报 | 按号。未同意或未认证不能当真实数据 |
| `/app/plans` | 写作计划 | 按号分组。启动、暂停、立即生成一篇、编辑 |
| `/app/plans/:id` | 计划详情 | 同一组操作，并编辑这个号的全部设置 |
| `/app/articles` `/app/articles/:id` | 文章列表和正文 | 预览、重写、反馈 |
| `/app/membership` | 会员 | 额度、订单、邀请、同意撤回 |
| `/app/inbox` | 通知 | 选题确认和任务结果 |
| `/admin` | 配置中心 | 模型、垂类、服务凭证。不是用户写作设置 |

主流程：注册并同意 → 绑定公众号 → 为这个号新建计划 → 定时或立即生成 → 草稿箱（认证企业号可另开自动发布）→ 文章页看结果。暂停后，工作台和计划页都有「启动」。立即生成一篇在暂停时仍写一次，不把定时恢复。

## 问题

严重程度：P0 用户完不成目标；P1 设置或生成会串号、看错或丢操作；P2 能用，但不符合「每个号有自己的性格」或后面的体验目标。

| 严重程度 | 问题 | 处理 |
| --- | --- | --- |
| P0 | 两个计划都暂停时，工作台把暂停计划滤掉，空状态写成「还没有写作方向」，只给「创建计划」。启动入口不在这一页 | 本 PR 修复。工作台列出全部计划，暂停的显示「启动」 |
| P0 | 计划页的按钮写「恢复」，放在一长串选题、日历、自动发布下面，标签也不是「启动」 | 本 PR 修复。列表和详情顶部是「启动 / 暂停」「立即生成一篇」「编辑」，并写下次生成时间 |
| P0 | 暂停后 `jobs.Create` 拒绝一切触发，所以「立即生成」也会失败，提示暂停原因 | 本 PR 修复。定时仍要求运行中。手动生成和重写可以在暂停时进行，并且不自动改回运行中 |
| P0 | 计划虽然带 `wx_account_id`，但创建之后不能改方向、风格、排版、篇幅、周期、开头结尾。卡片不显示号名，看起来像整站共用一套参数 | 本 PR 修复。`PUT /api/plans/{id}` 只改这一条。换号会被拒绝，并提示为另一个号单独建计划 |
| P0 | 关键词、读者、禁用词、显式垂类、选题方式、配图方式没有按计划落库。开发书把精细设置标成完成，禁用词实际只有全站敏感词 | 本 PR 修复。新列在 `plan_extra`，旧行默认空字符串，不覆盖已有开头、结尾和栏目 |
| P1 | 创建计划时客户端可以填任意 `asset_id` / `profile_id`，没有核对是不是这个用户的 | 本 PR 修复。不是自己的素材或画像会拒绝 |
| P1 | 付费档只要有匹配热点，就会盖过这个计划自己的轮换。两个号想错开选题时做不到 | 本 PR 部分修复。选题方式选「只按方向轮换」时不再套热点。默认「自动」保持原来的热点行为 |
| P1 | 连续 5 篇没有反馈会把计划暂停。暂停后用户在工作台看不到它 | 暂停规则保留。本 PR 让这条暂停计划重新出现，并可以启动 |
| P1 | 风格学习和样稿按用户各存一份，不是按号。两个号可以选不同的 `profile_id`，但「修改差异」仍写到用户那一条 | 留给 PR C 的账号人格。本 PR 不改学习数据，避免把已有画像拆丢 |
| P2 | 额度按用户合计，不按号拆开。高级版每天 5 篇要由各计划的「每天几篇」分 | 保留。这是会员额度，不是写作性格。界面仍写明各方向加起来不能超过上限 |
| P2 | 方向里没有垂类关键词时（例如「奶奶不当家」）会落到通用包。两个相近方向会共用同一包 | 本 PR 允许每个计划指定垂类。留空时匹配规则不变，旧计划生成结果不变 |
| P2 | 文章列表只有 `wx_account_id`，不显示号名。导航没有「当前正在看哪个号」 | 留给 PR B 的工作台和导航 |
| P2 | 新建表单把风格、排版、周期、开头结尾一次铺开，主要按钮容易被挤到屏幕外 | 本 PR 把启动和生成提到卡片顶部，精细项放在「这个号单独的设置」里。表单分层和手机端引导留给 PR B |
| P2 | 没有「绑定 → 选方向 → 200 字样稿 → 启动」的首跑引导，也没有标题打分、垂类结构和编辑打分 | PR B、PR C |
| P2 | 工作台「最近文章」显示的是接口返回的条数，不是单独的累计 | 留给 PR B，避免把列表长度说成成绩 |

没有把请求 Host 当成回调地址，也没有改短信尝试次数、额度扣减、事实核对、来源或自动发布的既有规则。

## 这次迁移

`plan_extra` 增加 `keywords`、`audience`、`banned_words`、`vertical_key`、`topic_mode`、`image_mode`。新库建表时就带这些列；已经存在的库用 `ADD COLUMN ... DEFAULT ''`，重复列忽略。已有开头、结尾、栏目、素材和画像原样保留。空的垂类、选题方式和配图按原来的自动行为运行。备份按整表读写，旧备份恢复时新列走默认空值，旧列不丢。

计划不能改绑到另一个号。已生成的文章仍留在原来的 `wx_account_id` 上。
